# AI有活 · 第二版迭代记录

读者：产品、开发与后续接手的 agent。日期：2026-10-13。

依据：用户提供的《网站第二版优化建议.docx》。本次在 dev 分支实现本地代码，没有推送、生产部署、修改数据库或调用付费模型。

## 已实现的第一阶段

- 站名采用文档首先提出的「AI有活」，母品牌保留 momorain；描述连接需求与能力，实际对接方式明确为人工。
- 首页收拢为平台介绍、服务内容、Demo展示、联系方式四个导航；流程与 FAQ 收入可展开说明，兼容历史首页锚点。
- 服务区和联系区均提供需求方、服务方两类入口，联系区约 60/40 布局，页脚不再重复整张二维码面板。
- `/requests/new`：需求问题、当前处理方式、期望结果、行业、使用者、类型、称呼和联系方式，分步校验与摘要预览。来自案例的有效 slug 带入真实名称、链接和提供者。
- `/providers/join`：基本资料、能力、代表作品、承接条件四组，最多六个作品；支持回退修改、拟公开/私密摘要、显式本地草稿保存/恢复/删除。
- 这两条流程均采用「整理→复制→微信自行发送」。没有在线接收后端，不显示提交成功、资料编号、审核通过或自动推荐结果。
- Demo 卡片以成果为主，有素材才显示图片；一个主要动作，展示已确认提供者和业务场景。精选最多两个，需有封面和真实成果，没有合格素材时整块隐藏。
- `/providers/momorain`：唯一真实团队的可分享介绍与作品页。旧项目通过明确 slug 清单署名，新项目不会默认算在团队名下。不将团队拆成虚构服务方。
- 详情增加提供者、原图查看、视频备用链接、体验条件附近说明，以及「我有类似需求 / 我也想展示作品」分流。原有案例结构、开源说明与交付标准保留。
- 咨询弹窗按需求/服务/作品来源区分标题，补充内容默认折叠；复制微信号反馈准确，失败提供手动复制，关闭恢复滚动和焦点。
- 项目后台写操作同步失效新增项目引用页面缓存，保留既有权限与发布检查。

## 保留为后续工作的能力

- 在线资料持久化、授权团队审核、资料状态查询与公开发布确认。
- AI 可行性分析、候选方案、真实服务方推荐与定向需求对接。
- 合作确认单版本、双方身份及确认记录、关键变更后重新确认。
- 真实封面、成片、对应输入样例与必要的授权核对。当前仓库 public 只有二维码；没有拿示意图或上游宣传图冒充本团队新成果。

这些能力不能在当前版本宣传为已实现。需要在线接收时，先设计数据表、权限、频控与保留规则，再将微信流程替换成真实提交；涉及模型时遵循 PLATFORM.md。

## 本地检查与限制

- `pnpm exec tsc --noEmit`
- `pnpm test:intake`：必填与多选、链接协议及凭证、联系方式、无效草稿/字段类型边界。
- `DB_HOST= DB_USER= DB_PASSWORD= DB_NAME= pnpm build`：只验证本地 fallback 模式，**不能作为生产数据与数据库迁移通过的证据**。
- 检查 prerender manifest：7 个固定公开页 + 6 个 fallback 项目 = 13 个静态路由。
- 检查构建 HTML 的四区块、入口、提供者链接和项目上下文；本机 HTTP 响应检查。
- 未完成真实浏览器视觉和微信内剪贴板/长按/移动端交互验收：Computer Use 的辅助功能和屏幕录制权限未就绪。样式已按 360/375/390/768/1440px 设计，尚不能记作设备验收通过。
